Strategy Paper · Agent Architecture

Agent Memory:
Explained

An agent is an autonomous system built on a foundation model and domain tools. This paper illustrates why, without a third layer — memory — even the most capable agent accumulates no institutional knowledge across interactions, and how a structured memory architecture turns agent deployments into compounding institutional assets.

Foundations
The three-tier memory model — episodic, semantic, procedural — originates in cognitive science (Tulving, 1972; Squire, 1987) and was formalised for AI agents in the CoALA framework (Sumers, Yao, Narasimhan & Griffiths, TMLR 2024), now the canonical academic reference in this space. The taxonomy is now implemented across a range of production frameworks — among them LangChain's LangMem SDK, Mem0, and Letta (the production evolution of the MemGPT research project) — each with different architectural trade-offs but converging on the same three-layer model. This paper's contribution is not the taxonomy itself — it is the application of that taxonomy to two specific enterprise agent archetypes, their interdependency, and the maturity ladder that maps memory investment to organisational adoption stage.

01 — The problem

The capability ceiling —
why tools alone aren't enough

A capable agent deployed today will be equally capable — and equally ignorant — six months from now. It will have handled thousands of interactions, sat inside dozens of workflows, watched your teams navigate decisions that took real judgement. None of that will have changed it. Ask it a question on day one and day two hundred, and it arrives at both from the same blank starting position. The throughput accumulates. The knowledge does not.

This is not a flaw in the underlying model. It is a gap in how agents are designed. Most deployments are built on two layers — language intelligence and domain tools — and stop there. The third layer, the one that turns a capable system into an asset that learns from its own deployment, is missing.

Throughput is not the same as learning. An agent that processes a thousand interactions and retains nothing from them stays as a beginner — indefinitely.

02 — The architecture

A memory architecture for agents

The CoALA framework (Sumers et al., TMLR 2024) — now the standard academic reference for cognitive architectures in AI agents — formalises memory across three distinct substrates, each with a different function and a different update rhythm. A range of production frameworks have since operationalised the same taxonomy: LangMem via LangGraph, Mem0 via a dual vector-and-graph store, Letta through agent-managed tiered memory, and others. The taxonomy is settled. What remains underexplored is how these three layers map differently onto different types of agent, and how an organisation should sequence investment across them as deployment matures. That is the work this section begins.

Episodic
What happened
The record of experience

Episodic memory is the agent's record of specific events: what was asked, what decisions were made, what outcomes followed. It is the equivalent of institutional memory in a human organisation — the collective recall of what has been tried and learned.

Without episodic memory, every interaction is context-free. The agent cannot refer back to a previous conversation, build on a prior decision, or notice that the same question has surfaced repeatedly across different users.

Semantic
What is known
The body of knowledge

Semantic memory is the agent's understanding of concepts, domain knowledge, standards, and shared vocabulary. It is what the agent knows about your organisation and your domain — distinct from what it has experienced.

A well-built semantic layer means the agent speaks your language and applies knowledge consistently — surfacing the right answer not just because the model is capable, but because the knowledge base it draws on reflects your specific domain, terminology, and operating context.

Procedural
How to act
The habits of working

Procedural memory is the agent's repertoire of actions: how it responds, which workflows it follows, what it does in a given situation. It is the layer closest to operational behaviour — and the one with the highest strategic ceiling.

At entry level, procedural memory is a set of rules and templates. As the organisation matures, this layer extends into workflow automation — the agent joins delivery pipelines, triggers processes, and eventually refines its own standard operating procedures based on what works. It is the layer that ladders most directly into organisational transformation.

These three layers are not independent. Episodic memory feeds semantic memory — recurring patterns in events become reusable facts. Semantic memory shapes procedural memory — what the agent knows governs how it acts. And procedural memory, as it matures, generates new episodes that feed the cycle again. How each layer is populated, and what it contains, depends significantly on what the agent is designed to do — which is the subject of the next section.

03 — The archetypes

Two agent archetypes

Most organisations approaching scaled AI deployment are, knowingly or not, building two distinct categories of agent. They have different audiences, different memory profiles, and different strategic roles.

Consumer agent

Delivers knowledge
to the many

Faces end users — employees, customers, or citizens — and surfaces the right knowledge at scale. Its value is measured by consistency, depth of context, and the degree to which it improves with use.

Episodic: Scoped to the individual user — their query history, past resolutions, preferences, and gaps. Each user's journey is a distinct episode the agent carries forward across sessions.
Semantic: Scoped to the organisation's domain — product knowledge, service policies, terminology, and evolving answers to the questions users actually ask. This layer is shared across all users and grows as usage patterns reveal gaps in what the agent knows.
Procedural: Scoped to service patterns — how the agent guides, routes, escalates, and anticipates. At an early stage these are fixed response templates. As the agent matures, procedural memory encodes adaptive workflows: knowing when to hand off, how to handle an edge case, and how to pre-empt a need before it is expressed.
Coding agent

Accelerates teams
building the consumer agent

Sits inside delivery teams and compresses the time from insight to deployed capability. Its value is measured by delivery velocity, code quality, and how effectively it carries institutional knowledge from sprint to sprint.

Episodic: Scoped to the sprint or delivery iteration — architectural decisions made, approaches tried and rejected, failures encountered. Each iteration is a discrete episode the agent carries into the next, preventing repeated mistakes and compressing ramp-up time across the team.
Semantic: Scoped to the discipline of software delivery — architecture patterns, technology standards, and delivery practice, anchored on agentskills.io as a shared, evolving knowledge standard. This layer is enriched over time as the team's own practice is folded back in, eventually becoming the organisation's own codified delivery standard rather than a generic import.
Procedural: The highest-leverage layer for the coding agent. Delivery work is inherently complex — architectural trade-offs, multi-step debugging, cross-team coordination, release sequencing. Procedural memory is what allows the agent to carry standard operating procedures for these workflows, execute them with decreasing human oversight, and progressively extend its own autonomy as confidence is established. The trajectory is from assisted generation to supervised execution to autonomous delivery — each step enabled by a richer procedural layer.

The transition from Assist to Embed is an operational decision — it requires integrating the agent into live workflows and accepting that the agent will act, not merely advise. The transition from Embed to Evolve is a governance decision — it requires trusting the agent's accumulated judgement enough to let it refine its own behaviour. Both transitions require deliberate investment in the memory layer.

Procedural memory is the layer that ladders into workflow. Most organisations stall at Assist because they have not invested in the memory architecture that would make Embed safe.

05 — Governance

When memory goes wrong — and how to prevent it

Layers one and two — reasoning and tools — produce behaviour that is largely predictable. Memory changes this. An agent whose episodic and procedural layers are accumulating is no longer purely deterministic: its responses are shaped by what it has experienced and what patterns it has been allowed to encode as behaviour. That is the source of its value — and its risk.

Not all three memory layers carry equal risk. Semantic memory, grounded in a curated knowledge base and surfaced through retrieval (RAG), is the most mature and lowest-risk layer. It retrieves facts rather than encoding behaviour — the governance challenge here is content quality and freshness, which organisations already manage for conventional knowledge bases. The harder governance problems sit in episodic and procedural memory, where patterns accumulate and eventually shape how the agent acts.

Memory does not improve an agent automatically. Without governance, it compounds errors as readily as it compounds knowledge.

Four failure modes in episodic and procedural memory warrant governance: encoding wrong patterns from unrepresentative early interactions; procedural ossification around workflows that have since changed; bias amplification where episodic memory reflects dominant user groups at the expense of others; and the correction problem, where a wrong pattern distributed across many memory nodes has no obvious location to fix.

Five governance responses address these directly: memory provenance so patterns can be traced; a decay and review cadence so procedural rules are revalidated rather than assumed permanent; a human gate before episodes promote into procedural behaviour; a controlled write pipeline separating read from write access; and drift detection to surface divergence before it compounds.

06 — Implications

Strategic implications

The memory architecture described in this paper points to five areas where deliberate choices — on investment, governance, and sequencing — will determine how much value an agent deployment compounds over time.

P1
Design for memory from the first deployment
Memory is not a feature to add later — it is an architectural decision. Agents built without memory scaffolding accumulate nothing. Every month of deployment without a memory layer is a month of institutional learning lost. Start small, but start on day one.
P2
Treat the coding agent as infrastructure, not tooling
The instinct is to think of coding agents as productivity tools for engineers. The right frame is infrastructure: the coding agent's memory — particularly its semantic grounding in delivery standards — is what makes every consumer agent deployment faster and more consistent. Invest in its memory tier accordingly.
P3
Anchor semantic memory on open standards where possible
Proprietary knowledge bases are slow to build and expensive to maintain. For the coding agent, anchoring semantic memory on a shared framework like agentskills.io means the agent starts with a high baseline of delivery knowledge — and the organisation contributes improvements back to the commons, compounding the ecosystem, not just its own deployment.
P4
Make the maturity stage a deliberate governance choice
The transition from Assist to Embed — where the agent joins live workflows rather than advising on them — requires an explicit organisational decision about trust, accountability, and oversight. It should not happen by drift. Establish the governance framework before reaching the Embed stage, not after.
P5
The first-mover advantage in AI is a memory advantage
A competitor who deploys the same model six months later starts with the same language capability. They cannot start with the same institutional memory. The knowledge accumulated in episodic, semantic, and procedural layers over months of real deployment is a strategic moat — intangible, but real and durable.
